# Ledger security & quality audit

Merged read-only review of API surface, auth, banks/sync, frontend build, and DB patterns. Line references verified against the repo at audit time unless marked **needs confirmation**.

---

## 1. Summary

**Overall posture:** Session-scoped SQL ownership is consistent on `/api/banks/*`; Better Auth with CSRF, CSP, body limits, and admin hooks is in good shape for a self-hosted finance app. Residual risk clusters around **deployment-dependent rate limiting**, **admin-wide backup exfiltration**, **bank sync correctness**, **unbounded reads**, and **money stored as SQLite REAL**.

### Top 5 risks

1. **Non-owner admins can download full DB backups** (all users, password hashes, sessions, encrypted bank creds) — [server/index.ts:258-276](/C:/Users/braydon/Desktop/Development/Web/Ledger/server/index.ts).
2. **Sync wipes all pending transactions per account** — user annotations and links lost — [server/banks/store.ts:71-105](/C:/Users/braydon/Desktop/Development/Web/Ledger/server/banks/store.ts).
3. **Sign-in / 2FA rate limits keyed on client IP** — shared bucket behind proxy or spoofable if `TRUST_PROXY` is wrong — [server/index.ts:93-99](/C:/Users/braydon/Desktop/Development/Web/Ledger/server/index.ts), [server/auth/index.ts:265-284](/C:/Users/braydon/Desktop/Development/Web/Ledger/server/auth/index.ts).
4. **Up to 50k transactions per API response** with planner SCAN on sample DB — [server/routes/finance/transactions.ts:67-76](/C:/Users/braydon/Desktop/Development/Web/Ledger/server/routes/finance/transactions.ts).
5. **Bank connect / session errors forward raw `Error.message`** (scraper/Playwright text) — [server/routes/banks.ts:53-54](/C:/Users/braydon/Desktop/Development/Web/Ledger/server/routes/banks.ts), [server/banks/sessions.ts:169-171](/C:/Users/braydon/Desktop/Development/Web/Ledger/server/banks/sessions.ts).

### What’s already done well

- Resource access expressed in SQL (`user_id`, joins to `bank_connection`); sharing uses central `access()`; invoice public tokens 144-bit, rate-limited checkout.
- AES-256-GCM for bank credentials/browser state; APIs do not return `*_enc` columns.
- Global `secureHeaders` + CSP, `/api/*` CSRF (`origin: env.appUrl`), 64 KiB body limit (statement route excepted).
- Admin impersonation / list-user-sessions disabled; owner guarded for role changes and owner account tampering.
- Parameterized SQL; webhook PayPal verification; zip import size filter (fflate `originalSize`).
- CI: `typecheck` and `test` pass; `bun audit` clean.
